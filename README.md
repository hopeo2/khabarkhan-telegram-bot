# ربات محتوای گروه (خبر + ورزش)

ربات تلگرامی که آخرین اخبار و اخبار ورزشی را از خبرگزاری‌های فارسی جمع می‌کند،
تکراری‌ها را حذف می‌کند و به‌صورت خلاصه در گروه شما منتشر می‌کند. همهٔ محتوا فارسی
است و روی زیرساخت **Telegram Serverless** (`tgcloud`) اجرا می‌شود؛ یعنی هیچ سروری
لازم نیست.

## چه کاری می‌کند؟

- هر چند ساعت یک «گزیده اخبار» و یک «گزیده ورزش» در گروه می‌فرستد.
- هر خبر **در یک پیام جداگانه** با عکس و متن خودش ارسال می‌شود (تیتر، خلاصه و
  لینک منبع زیر عکس). خبری که عکس ندارد به‌صورت پیام متنی می‌آید. با
  `/images off` همه‌چیز در یک پیام خلاصهٔ متنی جمع می‌شود.
- منابع: ایرنا، ایسنا، مهر، باشگاه خبرنگاران، بی‌بی‌سی فارسی، خبرآنلاین،
  یورونیوز فارسی، ورزش سه، طرفداری و مهر ورزشی.
- تیتر و خلاصه را تمیز می‌کند، لینک منبع را می‌گذارد و داستان‌های تکراری را
  (حتی بین خبر و ورزش) حذف می‌کند.
- ادمین‌ها با دکمه یا دستور می‌توانند فوراً ارسال کنند، فاصله را عوض کنند،
  ارسال خودکار را خاموش/روشن کنند و سلامت منابع را ببینند.
- بازهٔ سکوت (مثلاً ۲ تا ۷ صبح به وقت تهران) قابل تنظیم است.

## راه‌اندازی

### ۱) پیش‌نیازها

- Node.js ۱۸ یا بالاتر
- یک ربات در [@BotFather](https://t.me/BotFather)
- در BotFather: ربات → **Serverless** → روشن کردن، سپس
  **CLI Access → Access token** (قالب `app<id>:<secret>`)

### ۲) اتصال و انتشار

```bash
npm install
npx tgcloud login      # توکن CLI را وارد کنید
npx tgcloud push       # انتشار کد
npx tgcloud migrate    # ساخت جدول‌های دیتابیس (یک‌بار و بعد از هر تغییر schema)
npx tgcloud webhook sync
```

### ۳) تنظیم گروه و ادمین

1. ربات را به گروه اضافه کنید (برای ارسال، ادمین گروه باشد).
   با اضافه شدن، گروه مقصد خودکار ثبت می‌شود.
2. در **پیوی ربات** دستور `/claim` را بزنید تا اولین ادمین شوید.
   (برای قفل کردن از قبل، آیدی عددی خود را در `tgcloud/lib/config.js` داخل
   `BOOTSTRAP_ADMIN_IDS` بگذارید.)
3. `/panel` را بزنید و با دکمه‌ها آزمایش کنید.

اگر ربات را به گروه اضافه نکرده‌اید، می‌توانید شناسهٔ گروه را دستی بدهید:

```text
/setgroup -1001234567890
```

> برای دیدن شناسه‌ها، ربات را در گروه نگه دارید و `/id` بزنید.

## دستورهای ادمین

| دستور | کار |
|---|---|
| `/panel` | پنل مدیریت با دکمه‌های ارسال فوری |
| `/post` | ارسال فوری هر دو دسته |
| `/post خبر` یا `/post ورزش` | ارسال فوری یک دسته |
| `/status` | وضعیت، آخرین اجرا و آخرین نتیجه |
| `/settings` | نمایش تنظیمات |
| `/on` / `/off` | روشن/خاموش کردن ارسال خودکار |
| `/setinterval 3` | فاصلهٔ ارسال خودکار (۱ تا ۴۸ ساعت) |
| `/setcounts 2 1` | تعداد خبر و ورزش در هر ارسال (۰ تا ۵) |
| `/quiet 2-7` | بازهٔ سکوت به وقت تهران (`/quiet off` برای غیرفعال کردن) |
| `/images on` / `/images off` | عکس‌دار (هر خبر یک پیام) یا یک پیام خلاصهٔ متنی |
| `/setgroup` | ثبت گروه فعلی (در گروه) یا `/setgroup -100...` |
| `/addadmin 123456` | افزودن ادمین (یا ریپلای روی پیام کاربر) |
| `/deladmin 123456` | حذف ادمین |
| `/feeds` | بررسی سلامت منابع خبری |

دستورهای عمومی: `/start`، `/help`، `/id`، `/claim`.

## زمان‌بندی خودکار (مهم)

Telegram Serverless **کرون داخلی ندارد**؛ کد فقط وقتی اجرا می‌شود که تلگرام یک
آپدیت بفرستد. بنابراین یک «تیک» بیرونی لازم است. این پروژه برای GitHub Actions
آماده شده است:

1. پروژه را در یک ریپوی GitHub (ترجیحاً خصوصی) push کنید:

   ```bash
   git add -A
   git commit -m "Persian news and sports group bot"
   git branch -M main
   git remote add origin git@github.com:<user>/<repo>.git
   git push -u origin main
   ```
2. در GitHub → Settings → Secrets and variables → Actions، یک secret به نام
   `TGCLOUD_TOKEN` بسازید و همان توکن CLI را در آن بگذارید.
3. فایل `.github/workflows/auto-post.yml` هر ۳۰ دقیقه اجرا می‌شود و
   `endpoints/scheduler` را صدا می‌زند. خود ربات تشخیص می‌دهد که آیا فاصلهٔ
   تنظیم‌شده (پیش‌فرض ۳ ساعت) گذشته است یا نه؛ پس اجرای مکرر باعث ارسال تکراری
   نمی‌شود.
4. برای تست دستی: Actions → Auto post → Run workflow → گزینهٔ `force`.

نکته‌ها:

- GitHub ممکن است اجرای زمان‌بندی‌شده را چند دقیقه به تأخیر بیندازد.
- اگر ریپو ۶۰ روز فعالیت نداشته باشد، GitHub زمان‌بندی را غیرفعال می‌کند.
- توکن CLI اجازهٔ انتشار دارد؛ آن را فقط در secret نگه دارید و ریپو را خصوصی کنید.
- جایگزین: روی هر سرور/کامپیوتری که همیشه روشن است، هر ۳۰ دقیقه
  `npm run tick` را اجرا کنید. همین کار را می‌کند و به GitHub وابسته نیست.

## ساختار پروژه

```text
tgcloud/
├─ handlers/
│  ├─ message.js          # دستورها و پنل
│  ├─ callback_query.js   # دکمه‌های inline
│  └─ my_chat_member.js   # ثبت خودکار گروه هنگام اضافه شدن ربات
├─ endpoints/
│  └─ scheduler.js        # نقطهٔ ورود تیک خودکار
├─ lib/
│  ├─ config.js           # ثابت‌ها (ادمین/گروه اولیه، پیش‌فرض‌ها)
│  ├─ sources.js          # فهرست فیدهای RSS
│  ├─ rss.js              # خواندن RSS/Atom
│  ├─ rank.js             # حذف تکراری و رتبه‌بندی
│  ├─ digest.js           # ساخت متن/کپشن فارسی هر خبر
│  ├─ content.js          # جمع‌آوری و انتخاب محتوا
│  ├─ publish.js          # ارسال و ثبت در دیتابیس
│  ├─ jobs.js             # منطق زمان‌بندی/قفل/فاصله
│  ├─ settings.js         # تنظیمات در SQLite
│  ├─ persian.js          # تاریخ شمسی، اعداد فارسی، پاک‌سازی HTML
│  ├─ ui.js               # متن‌ها و کیبوردها
│  └─ notify.js           # اطلاع به ادمین‌ها
└─ schema.js              # جدول‌های settings / posted_items / post_log
```

## سفارشی‌سازی

- **منابع:** `tgcloud/lib/sources.js` را ویرایش کنید. هر فید باید `id`، `name`،
  `category` (`news` یا `sports`)، `priority` و `url` داشته باشد.
- **پیش‌فرض‌ها:** `tgcloud/lib/config.js` (فاصله، تعداد، بازهٔ سکوت).
- **ادمین/گروه اولیه:** همان فایل؛ یا از داخل تلگرام با `/claim` و `/setgroup`.
- **متن پست‌ها:** `tgcloud/lib/digest.js` (متن پیام و کپشن عکس‌ها).

بعد از هر تغییر:

```bash
npx tgcloud push
# اگر schema.js عوض شده:
npx tgcloud migrate
```

## عیب‌یابی

| مشکل | بررسی |
|---|---|
| ارسال انجام نمی‌شود | `/status`؛ «گروه مقصد تنظیم نشده» یعنی ربات را به گروه اضافه کنید یا `/setgroup` بزنید. |
| ربات در گروه پیام نمی‌دهد | ربات باید در گروه ادمین باشد و اجازهٔ ارسال داشته باشد. |
| منبعی خالی است | `/feeds`؛ ممکن است فید موقتاً در دسترس نباشد یا از IP تلگرام بلاک شده باشد. |
| پستی ارسال نشد | شاید همهٔ آیتم‌ها تکراری/قدیمی بودند؛ `/status` و `/feeds` را ببینید. |
| عکس‌ها نمی‌آیند | بعضی سایت‌ها اجازهٔ دانلود عکس به تلگرام نمی‌دهند؛ همان خبر با متن کامل ارسال می‌شود. با `/images off` همه‌چیز به یک پیام متنی تبدیل می‌شود. |
| زمان‌بندی اجرا نمی‌شود | Actions → Auto post → آخرین اجرا؛ وجود secret `TGCLOUD_TOKEN` را بررسی کنید. |
| وبهوک ناهماهنگ | `npx tgcloud webhook sync` |

## محدودیت‌های شناخته‌شده

- فقط RSS/Atom؛ برای بازنویسی با هوش مصنوعی باید بعداً یک سرویس اضافه شود.
- عکس‌ها از خود فید می‌آیند؛ اگر خبرگزاری عکسی نداشته باشد (مثل یورونیوز) خبر
  متنی منتشر می‌شود. کیفیت عکس به همان چیزی است که منبع می‌دهد.
- در حالت عکس‌دار، هر خبر یک پیام جداگانه است؛ پس هر اجرا چند پیام در گروه
  می‌گذارد. اگر پیام‌های کمتر می‌خواهید `/images off` بزنید.
- فاصلهٔ واقعی ارسال به تأخیر cron بیرونی هم بستگی دارد.
- هر آیتم فقط یک‌بار منتشر می‌شود؛ برای ارسال دوباره باید ردیف آن از جدول
  `posted_items` حذف شود.
